# АИТЕХ · главная по концепции A «Сигнал»

Рабочий адаптивный сайт. Основа — концепция A «Сигнал» (`../a-signal/`), которую выбрал заказчик: двенадцать блоков, шрифты, сетка, тексты и движение перенесены из неё. Задание — `../brief/aixtex_claude_brief_v3.md`. В режиме согласования на странице есть панель с семью палитрами, по умолчанию оранжевая палитра A.

Стек: Astro 5 (статическая сборка), TypeScript, обычный CSS, GSAP с ScrollTrigger. Живого WebGL на странице нет. Сцена Three.js и компоненты раундов 3–4 лежат в `_archive/round4/` и не собираются.

## Запуск

Нужен Node.js 22.18 или новее.

```bash
cd site
npm install
npm run dev        # http://localhost:4321
npm run build      # проверка типов (astro check) и сборка в dist/
npm run preview    # просмотр собранной версии
```

## Режимы

Режим задаётся переменными окружения в `.env` (образец — `.env.example`):

| Переменная | Значение | Что делает |
|---|---|---|
| `PUBLIC_REVIEW_MODE` | `true` (по умолчанию) | Режим согласования: панель палитр, `noindex, nofollow`, robots.txt закрывает сайт, неподтверждённые факты видны с пометкой. |
| | `false` | Публичная версия: панели нет, палитра фиксирована, есть canonical, robots.txt открыт, sitemap.xml заполнен, неподтверждённые факты скрыты. |
| `PUBLIC_APPROVED_PALETTE` | `signal`, `olive`, `ultra`, `steel`, `mint`, `iris` | Палитра публичной версии. На страницу попадает только она. |
| `PUBLIC_SITE_URL` | например `https://aixtex.ru` | Адрес сайта для canonical, og:image и sitemap. |
| `BASE_PATH` | `/` или подпапка | Нужна, если сайт лежит не в корне домена (GitHub Pages). |

```bash
PUBLIC_REVIEW_MODE=false PUBLIC_APPROVED_PALETTE=signal PUBLIC_SITE_URL=https://aixtex.ru npm run build
```

## Публикация на GitHub Pages

Версия для согласования лежит в папке `v3/` в корне репозитория и открывается по адресу https://sgoryanskya.github.io/aixtex_concept/v3/. Pages публикует ветку `main` из корня, поэтому в `v3/` хранится готовая сборка, а не исходники. После правок сборку нужно обновить и отправить в `main`:

```bash
cd site
PUBLIC_REVIEW_MODE=true BASE_PATH=/aixtex_concept/v3/ PUBLIC_SITE_URL=https://sgoryanskya.github.io npm run build -- --outDir dist-pages
rm -rf ../v3 && cp -R dist-pages ../v3
```

Сборку нельзя направлять сразу в `../v3`: при папке вне `site/` Astro кладёт рядом свои служебные файлы.

## Режим согласования

- **Панель палитр.** Кнопка «Палитра» стоит там, где в A был переключатель концепций: справа внизу, на телефоне справа вверху. Выбор сохраняется в адресе и в браузере.
- **Порядок выбора палитры при открытии:** `?palette=` в адресе → последний выбор (`localStorage`, ключ `aixtex.palette.v2`) → «Чёрный / оранжевый». Ключ сменён, чтобы бронза, сохранённая в прошлых раундах, не перебила новую палитру по умолчанию.
- **Параметр `?studio=0`** скрывает панель, `?studio=1` показывает.
- **Параметр `?hero=value`** показывает запасной вариант заголовка («Сложное / Ценное»). По умолчанию стоит выбранный 4 ноября «Сложное / Управляемое». Постоянный вариант задаётся в `HERO_VARIANT` в `src/data/content.ts`. Действует только на композицию A, то есть на оранжевую палитру и `?art=orig`.

- **Параметр `?hero-art=b`** показывает вариант Б первого экрана у оранжевой палитры: к правому краю пучок скручивается в две пряди, импульсы идут по прядям. У оливы вариант Б — латунный бюст вместо стеклянного чипа. У ультрамарина, стали, мяты, градиента и перелива вариант Б совпадает с А.
- **Параметр `?art=orig`** показывает исходные кадры A (оранжевый пучок, мраморный бюст) для сравнения.

```text
/?palette=olive&studio=1    олива и латунь, панель на месте
/?palette=ultra             ультрамарин
/?palette=steel             сталь и жемчуг
/?palette=mint              мята и шампань
/?palette=iris              оранжевый перелив
/?hero=value                запасной вариант заголовка
/?hero-art=b                скрутка пучка у оранжевой палитры, бюст у оливы
/?art=orig                  исходные кадры концепции A
```

### Концепции палитр (раунд 5)

Каркас у всех палитр общий: те же двенадцать блоков, тексты, сетка и движение A. Уголков, меток обреза, крестиков, линеек по краям блоков, точечных и линейных сеток фона нет ни у одной палитры: заказчик попросил их убрать. На баннере хаос слева собирается в порядок справа, в точке, куда приезжает камера при прокрутке. Оранжевая палитра не меняется. Олива повторяет её в своих цветах, со своим кадром на первом экране. У четырёх других свой сюжет баннера, свой первый экран (ниже) и своя отделка блоков. Тема «Градиент» из части 9 удалена по решению заказчика (часть 10):

| Палитра | Концепция | Баннер | Блоки |
|---|---|---|---|
| Олива и латунь | как оранжевая, в цветах оливы | спутанные тёмные нити входят в стеклянный ИИ-чип с латунной разводкой и выходят ровными латунными линиями, по линиям бегут импульсы; второй кадр — латунный бюст (`?hero-art=b`) | как у оранжевой палитры, в цветах оливы |
| Ультрамарин | «Стеклянная лента», референс заказчика «вариант цвета aixtex» | в глубоком синем стеклянная лента переливается от красно-розового через белый к синему, по её верхней кромке бежит белый блик; людей в кадре нет | мягкий синий и тёплый отсвет из углов тёмных глав, тонкая линия в цветах ленты на стыках, перелив ленты в цифрах манифеста, кнопках, метках и логотипе подвала; в финале та же лента дугой над призывом |
| Сталь и жемчуг | «Металл и чистое стекло» | смятый лист стали к правому краю выглажен в ровные складки | чистое стекло без зерна только там, где текст лежит на картинке: колонна первого экрана, панель роли у ассистента, текст отраслей, док; каталог без стекла и размытия; шлифованная планка на стыках, хром в крупных словах |
| Мята и шампань | «Гладь воды» (часть 10) | нарисован кодом (`scripts/art/heroes/mint.js`, шейдер WebGL): тёмная вода в сумерках, на горизонте полоса света шампани, над ней мягкое мятное свечение. Слева рябь рассыпает свет бликами (хаос), к правому краю вода стихает в зеркало, и свет ложится ровными линиями зыби (порядок). Свет у горизонта медленно дышит, по горизонту изредка проходит импульс | в главах мягкий свет мяты и шампани, тонкая линия на стыках и прямые линии над цифрами манифеста |
| Оранжевый перелив | «Световой занавес» (часть 10), папка заказчика с оранжевым: WMT AI, Nexora Biosystems, Kontour | нарисован кодом (`scripts/art/heroes/iris.js`, WebGL): слева тонкие спутанные нити оранжевого, розового и сиреневого света (хаос), к центру они сходятся в один ровный световой занавес с лучами через равный шаг (порядок); по нижней кромке занавеса бегут блики | тёплый свет снизу и розово-сиреневый отсвет в тёмных главах, линия перелива на стыках, метка — три растущих столбика, перелив в цифрах, кнопках и логотипе подвала, панель диалога с переливающейся кромкой |

Углы у каждой палитры одни на весь сайт. Мята — острые везде: порядок в концепции — прямые линии, как ровные линии света на спокойной воде, поэтому скруглений нет ни у кнопок, ни у дока, ни у карточек, ни у меток. Ультрамарин — мягкие везде: у света и стеклянной ленты нет углов; кнопки, плашки и док — капсулы, карточки, панели и формы — 22px, поля и реплики — 14–16px. Сталь — мягкие везде, как у шлифованного прибора: органы управления — капсулы, карточки, панели и формы — 18px, поля и реплики — 14px. Перелив — мягкие везде, как у светового занавеса: капсулы, карточки и панели 22px. Оранжевая и олива — как в A.

У четырёх других палитр первый экран свой: другая раскладка, другие слова заголовка и другое движение. Кадр баннера и общий каркас (липкая сцена 240vh, камера по прокрутке, док «Обсудить задачу») остаются общими.

- Часть 9 усилила две прежние палитры. Ультрамарин по референсам заказчика: фон не чёрный, а глубокий тёмно-синий со стальным светом (и на первом экране — кадр ленты лежит на нём в режиме «светлее»), карточки «Что меняется» синие со светлой кромкой, как сетка «Процесс внедрения», заголовки светлых глав синим градиентом, как «Apple», цифры манифеста персиковые. Олива: чёрное в кадре стало оливковым бархатом, свет латуни стоит на ровных линиях, по стеклу чипа раз в восемь секунд проходит блик, «Управляемое», цифры и кнопки — полированная латунь, тёмные главы в том же бархате с латунными стыками.
- Тексты первого экрана каждой палитры, включая скрытый `<h1>` для поиска и экранных дикторов, лежат в `HERO_LOOKS` в `src/data/content.ts`.
- Разметка в `src/components/Hero.astro`: по слою `.hx--<палитра>` на каждую. В публичной версии на странице остаётся только слой утверждённой палитры (`APPROVED_PALETTE`).
- Стили в `src/styles/hero-looks.css`, движение в `src/lib/hero-looks.ts`. `signal.ts` при открытии и при смене палитры выбирает композицию (`mountHero`): старая откатывается целиком через `gsap.context`, новая собирается без повторного появления.
- Часы стали показывают время по Москве (`Intl.DateTimeFormat`, зона `Europe/Moscow`) и обновляются раз в 15 секунд. Кадры мяты и перелива нарисованы кодом заранее и лежат картинками, как у стали; дыхание света у горизонта мяты — CSS (`.mi-dawn`), при уменьшенном движении оно стоит.
- У оливы два кадра: стеклянный чип по умолчанию и бюст по `?hero-art=b`. Импульсы для каждого заданы отдельно (`olive` — восемь ровных линий из чипа, `olive-b` в `src/data/hero-paths.json`). Блик ультрамарина — SVG в разметке первого экрана (`Hero.astro`, путь `RIBBON` снят с верхней кромки ленты в координатах кадра 1600×900, поэтому блик едет вместе с камерой); у ультрамарина пути импульсов в `hero-paths.json` пустые, у мяты импульс идёт по горизонту, у перелива — по нижней кромке занавеса.
- Лента ультрамарина в финале — тот же кадр `hero-a-ultra.webp`, повёрнутый на 180° (`.end__art` в `Contact.astro`, стили в конце `concepts.css`); в разметке она есть, только если ультрамарин может быть на странице.

#### Блок «Внутри агента» по палитрам

У каждой палитры, кроме оливы, своя сцена из одной логики «снаружи один сотрудник, внутри три слоя». Фарфоровые плиты A у оранжевой палитры заменены веером нитей по просьбе заказчика; прежний вариант есть в истории git (коммит `4221d9a`). Тексты слоёв общие, сцены строятся кодом, без картинок.

| Палитра | Сцена | Движение по прокрутке |
|---|---|---|
| Сигнал · веер нитей в одну линию | из плашки «Виртуальный сотрудник · в работе» выходит широкий веер гладких нитей (кривые Безье с общим градиентом, под ними лёгкая оранжевая глазурь); на нитях двенадцать глазурованных бусин-составляющих с подписями на светлых плашках | фронт идёт слева направо: нити сходятся в линию, бусины садятся на неё и становятся оранжевыми, подписи гаснут; под линией по очереди появляются три слоя. Нити серые, там где сошлись — оранжевые |
| Олива · веер нитей | сцена оранжевой палитры в цветах оливы | как у оранжевой |
| Ультрамарин · нейронная матрица | тёмная витрина внутри светлой секции, три стеклянные пластины-слоя, на каждой четыре нейрона-составляющие; соседние слои связаны каждый с каждым, выход — узел «Виртуальный сотрудник» и луч | сигнал проходит матрицу слой за слоем, связи загораются; потом строки сходятся к оси, матрица становится одним лучом, пластины разгораются, появляются подписи слоёв |
| Сталь · разборка прибора | закрытый корпус из трёх пластин в изометрии, над ним плашка «Виртуальный сотрудник · в работе»; верх пластин — светлое жемчужное стекло, торцы — шлифованная сталь; на каждой пластине четыре узла — составляющие слоя; слева таблица «Поз. · Слой · Состав», справа выноски 01–03 | пластины расходятся по высоте, проступают узлы, связи между узлами соседних слоёв и ось; сигнал входит с углов верхней пластины, проходит слои сверху вниз, собирается в центре нижней и по оси поднимается к плашке |
| Мята · одна полоса, три полосы | капсула «Виртуальный сотрудник · в работе» из трёх полос металла палитры | капсула раскрывается в три полосы-карточки, по каждой бегут составляющие слоя |

- Составляющие слоёв (`parts`) и подписи рисунков (`face`, `status`, `spec`) лежат в `INSIDE` в `src/data/content.ts`. Составляющие взяты из текста слоя по одной, новых фактов в них нет.
- Разметка в `src/components/InsideLooks.astro`, стили в `src/styles/inside-looks.css`, движение в `src/lib/inside-looks.ts`. `signal.ts` выбирает сцену при открытии и при смене палитры (`mountInside`), как и первый экран.
- Веер сигнала и матрица ультрамарина строятся в скрипте: нити сигнала заданы с постоянным зерном, поэтому картина одна и та же при каждой загрузке; веер не заходит под заголовок и нижнюю строку.
- У стали сигнал бежит, только пока блок на экране, и не бежит при уменьшенном движении. Все сцены перерисовываются после пересчёта ScrollTrigger (`redraw` в `run()`): иначе при прыжке прокрутки в конец блока сцена оставалась в начальном кадре.
- На телефоне и при `prefers-reduced-motion` сцены показываются сразу в конечном состоянии (на телефоне у сигнала — сеть справа уже стягивается в линию, у ультрамарина — светящаяся матрица); составляющие у мяты бегут, только пока блок на экране, и стоят при уменьшенном движении.

Все правила лежат в `src/styles/concepts.css` и привязаны к `:root[data-palette='…']`, поэтому оранжевую палитру они не задевают. Импульсы на первом экране идут по линиям каждого баннера: пути лежат в `src/data/hero-paths.json`, стиль импульса для каждой палитры задан в `heroPulses()` в `src/lib/signal.ts`. У оранжевой палитры и по `?art=orig` импульсы идут по проводам, как в A.

Цвета в стилях не прописаны напрямую: палитра задаёт базовые цвета (`--ink`, `--t1`, `--signal`, `--fog`, `--d1` и другие, имена как в A), прозрачные оттенки и линии считаются из них через `color-mix`.

У каждого факта в `company.ts` есть статус: `confirmed` (подтверждено заказчиком), `site` (взято с aixtex.ru, показывается), `unverified` (в публичной версии скрыто). Что ждёт подтверждения, перечислено в `CONTENT_STATUS.md`.

## Изображения

- `public/img/art/` — кадры в металле палитры:
  - первый экран (`hero-a-*`, `hero-b-*`): у оранжевой палитры два варианта кадра A; у оливы два сгенерированных кадра, стеклянный чип (`hero-a`) и бюст (`hero-b`); у ультрамарина один сгенерированный кадр со стеклянной лентой в обоих файлах; у стали свой баннер, `hero-b` повторяет `hero-a`; у мяты кадр рисует скрипт, картинка скрыта;
  - стеклянная девушка из концепции C (`glass-*`);
  - семь сцен каталога (`scene-*`, 1120×840) и шесть отраслей (`ind-*`, 1040×1040). Сюжеты A, сгенерированы заново в Figma одной серией: фарфор, мрамор, акцентные предметы из меди, один свет и один ракурс. Колл-центр в новой композиции: два ряда мест и низкая медная консоль, без кольца.

  Набор на каждую палитру задаёт поле `art` в `src/data/palettes.ts`: пять наборов `signal`, `olive`, `ultra`, `steel`, `mint`, по 16 кадров. Адрес картинки собирает встроенный скрипт в `<head>`, при смене палитры `theme-controller` подставляет новый кадр.
- `public/img/*.webp` — исходные кадры A, показываются по `?art=orig`.
- `public/og.jpg` вырезан из `hero.webp`.

Кадры пересобираются скриптами из `scripts/art/` (Python 3, numpy, scipy, Pillow), путь — корень репозитория:

```bash
python3 site/scripts/art/hero.py . /tmp/art           # оранжевая палитра: hero-A-signal.png и hero-B-signal.png
node site/scripts/art/heroes/render.cjs /tmp/art steel,mint,iris   # баннеры и их пути импульсов; olive и ultra не передавать
python3 site/scripts/art/glass.py site/scripts/art/src/glass-girl.png /tmp/art
python3 site/scripts/art/scenes.py site/scripts/art/src/scenes /tmp/art        # каталог и отрасли: кадровка и медь в металле палитры
python3 site/scripts/art/hands.py site/scripts/art/src/hand-live.png site/public/img/art   # «Перелив», «Кто это»: живая рука и рука из точек
```

Блок «Кто это» у «Оранжевого перелива» (часть 11, референсы заказчика WMT AI и «Релевантер»): вместо стеклянной девушки две руки тянутся друг к другу указательными пальцами. Справа живая рука — кадр сгенерирован в Figma (`scripts/art/src/hand-live.png`, 1376×768, один запуск Nano Banana), `hands.py` подкрашивает его: оранжевый свет по нижней кромке, сиреневый по верхней, предплечье к краю темнее. Слева рука из точек — зеркало живой руки в полутоне, повёрнутое на 7°: `hands.py` пишет сетку точек в `public/img/art/hand-dots.json` (три байта на точку) и геометрию слоя (искра, запястье, место фото), `Assistant.astro` берёт геометрию при сборке, `src/lib/hands.ts` рисует точки в canvas. По прокрутке точки слетаются из потоков работы слева и собирают руку от запястья к кончику пальца, живая рука подходит навстречу, в зазоре загорается искра, над ней — результат роли. Линии входов идут в запястье руки из точек. При смене роли по руке проходит волна света и искра вспыхивает, без смены — тихая волна раз в пять секунд. Слой рук есть в разметке, только если «Перелив» может быть на странице.

Исходники лежат в `scripts/art/src/`: стеклянная девушка (`glass-girl.png`, 1024×1024, концепция C) и сцены каталога и отраслей (`scenes/*.png`, Figma, файл `sPkEzkAdNus99NARYOYM4P`). `scenes.py` приводит фон к белому, вписывает сцену в кадр с одинаковыми полями, находит медь по насыщенности и поворачивает её оттенок к металлу палитры. У «Сигнала» медь остаётся как есть. В холодных палитрах мрамор и фарфор дополнительно уводятся в нейтральный (`NEUTRAL` в `scenes.py`), чтобы тёплый камень не спорил с синим или стальным металлом.

Кадры оливы и ультрамарина сгенерированы в Figma и доведены вручную: свет, кадровка, металл палитры. В части 8 раунда 5 оба кадра заменены (два запуска): у оливы золото чипа уведено к латуни палитры, фон к тёмной оливе; у ультрамарина верх середины чуть затемнён под заголовок. `render.cjs` с `olive` или `ultra` перепишет эти картинки и их пути импульсов, поэтому запускать его только для стали, мяты и перелива. Баннеры стали, мяты и перелива рисуются кодом: `scripts/art/heroes/<палитра>.js` выполняется в Chrome без окна (у стали и мяты шейдер WebGL, у перелива — сложение полос света в WebGL), общие функции лежат в `heroes/lib.js`, запуск и цвета палитр — в `heroes/render.cjs`. Кадр строится в 4000×2250, затем уменьшается до 2000×1125 и сохраняется в webp с качеством 84 как `hero-a-<палитра>.webp` и `hero-b-<палитра>.webp`. Тот же запуск переписывает пути импульсов в `src/data/hero-paths.json`. Нужны Google Chrome и `playwright-core` из `node_modules` сайта.

`scenes.py` перед перекраской в палитры кроме оранжевой сводит перелив металла к одному оттенку (`finish.py`, `matte_scene`). Резкость, блики и фон не трогаются: зерно и гашение бликов из раунда 5 убраны, потому что кадры от них мутнели. Оранжевая палитра и стеклянная девушка идут без отделки. Готовые PNG переводятся в webp с качеством 84.

## Поведение

- Форма заявки обычная: имя, компания, телефон с маской +7 (для номера другой страны — начать с «+»), почта, описание задачи и согласие с политикой. Обязательные поля отмечены звёздочкой, ошибки показываются под полем после ухода с него и при отправке. Если задан `PUBLIC_FORM_ENDPOINT`, заявка уходит туда POST-запросом в JSON (`name`, `company`, `phone`, `email`, `task`, `consent`, `page`), при ошибке форма предлагает телефон и почту. Пока адреса нет, кнопка открывает письмо в почтовой программе посетителя с заполненными полями. Своего бэкенда и хранения заявок у сайта нет.
- Клавиатура: ссылка «К основному содержанию», роли в блоке «Кто это» (стрелки, Home, End), панели решений на `<dialog>` (Escape, фокус возвращается), меню, FAQ, панель палитр.
- `prefers-reduced-motion`: длинные прокрутки первого экрана, диалогов и анатомии превращаются в обычные блоки, импульсы и появления выключены. Первые экраны четырёх палитр показываются сразу собранными, свет мяты не дышит, рука из точек у «Перелива» сразу собрана и стоит, часы стали идут. Сцены блока «Внутри агента» тоже показываются в конечном состоянии.
- Без JavaScript текст виден целиком, подробности решений раскрыты прямо в странице.
